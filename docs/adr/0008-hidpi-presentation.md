# 0008: 高分屏（HiDPI）呈现

- 状态：Accepted
- 日期：2026-11-10
- 适用范围：sena-rs 宿主呈现层（与具体 exe 无关，不涉及 PAL 语义）。本作的验证都在 `--patch mai` 下进行。

## 问题

在 Retina 屏上：
- **文字发虚**：窗口按逻辑尺寸 1280×720 创建，物理表面是 2560×1440，几何和鼠标映射都是对的。但所有宿主绘制的文字（ADV 正文、名字、backlog）都先按 1280×720 光栅化，再放大 2 倍，所以发虚。
- **画面拉伸**：窗口比例不是 16:9 时（例如这台 3024×1964 的屏全屏），画面按两个轴分别缩放，被拉伸变形。

## 原生证据

不涉及。这是宿主呈现层的改动，PAL 的逻辑分辨率、脚本、命中测试和存档都保持不变。原生的 `ChangeAspect` 四种缩放策略仍然没有对应实现（只打印警告）。

## 决策 / 实现

sena-rs `iroha` 分支，提交 `edbc0d3`。英文文档：`reverse/hidpi-presentation.md`。

1. **等比缩放加黑边**
   - `scene::letterbox_rect` 是唯一的 PAL→设备映射：等比缩放、居中、四周黑边，边缘对齐整像素。
   - wgpu 用 `set_viewport` 加 scissor；软件合成器先合成视口，再居中拷贝。
   - 鼠标映射走同一个矩形，仍保留原生的向零截断和有符号越界值。
2. **高清文字**
   - 文字密度 = 缩放倍数的整数部分（上限 4），所以高清表面只会被放大，不会缩小。
   - 矢量字体按 d 倍字号重新光栅化，描边和阴影核按 d 等比放大；d=1 时和原来的十字、菱形核逐像素一致。
   - 位图字体和原生标记文本退化为放大，几何一致，但不会更清晰。所以不加补丁（位图字体）时不生成高清副本。
   - 高清像素作为 sprite 表面的副本，绑定当时的 generation。表面像素被任何路径改动后，副本自动失效。
   - 只有设备渲染器读取高清副本；headless PNG、存档缩略图、转场截帧仍然用逻辑像素。
   - 覆盖范围：ADV 正文（含逐字显示、文字动画阈值、TIPS 着色、等待标记）、名字、backlog。
3. **backlog 呈现缓存**：输入状态（布局 generation、滚动、悬停、颜色、密度等）不变时，不再每帧重绘。2x 下原来每帧约 6.5ms，现在和 1x 相当。
4. **诊断工具**
   - headless 新增 `--diagnostic-device-size WxH`：模拟物理表面，输入和 PNG 都走设备合成。
   - wgpu 的 `--window-dump-frame-at` 改为真实 GPU 回读：离屏重录同一个 pass，窗口被遮挡时也能导出。

## 运行时验证

- **测试**：pal-vm 共 484 个（含集成测试）全部通过，新增 8 个，覆盖：
  - 黑边矩形和密度计算；
  - 鼠标映射；
  - 放大函数；
  - 高清字形位置；
  - 高清副本失效；
  - 高清 ADV 合成的几何缩放。

  pal-script、pal-asset、pal-disassembled 也都通过。编译警告数和改动前相同。
- **逻辑输出无回归**：以改动前的提交为基准，单独编了一份二进制（`work/re/base-target`），在相同输入下逐帧对比：
  - `--patch mai` 下第 900 到 12000 帧之间的 7 帧，以及不加补丁时的第 4200、9000 帧，PNG 逐字节一致，PC 轨迹完全相同。
  - backlog 打开、滚动、回滚、点击 4 个状态也一致。
- **高清效果**（headless，`work/diag/hidpi/`）：
  - 2560×1440：ADV 文字明显更锐利，字形位置不变（`zb3.png` 修复前 / `za3.png` 修复后）。
  - backlog 名字、正文、悬停底板正常（`b_log.png`）。
  - 3024×1964：上下各 131 像素黑边，文字用 2 倍高清层再线性放大 1.18 倍（`r5856_s.png`）。
- **真实窗口（wgpu）**：
  - 1280×900 逻辑尺寸的窗口（物理 2560×1800），GPU 回读确认上下黑边正确（`wgpu_tall.png`），没有 wgpu 校验错误。
  - 软件渲染路径的窗口导出也正常。

## 未解决

- 脚本自己画在游戏 sprite 上的文字（`sp_text` 等）和图片素材本身仍是逻辑分辨率，只做放大。
