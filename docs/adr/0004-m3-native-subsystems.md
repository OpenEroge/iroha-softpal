# 0004: M3 本作原生子系统：版本识别、ANI 动画、action 扩展、存档标签、TIPS

- 状态：Accepted；按钮与 action 的交互（EXTRA 子菜单偏移）仍为 Proposed
- 日期：2026-11-09
- 适用范围：`trenka.exe` sha256=`1038558f…09fd`，`dll/Pal.dll` sha256=`2ef61fc3…8463`；sena-rs `iroha` 分支 `4581a9d`..`073f950`
- 引擎侧记录：`sena-rs/reverse/iroha-native-profile.md`

## 1. 版本识别与 registered 契约共用（`4581a9d`）

**原生证据**：逐个 handler 比较了 trenka 与 sena 的 registered（Totsulover）实现，比较内容包括参数个数、调试字符串和调用的 PAL 函数。下面这些坐标完全一致：

- SE：5:0–14（其中 5:1 只弹 3 个参数，正好解决了 ADR-0003 里提到的“5:1 参数个数”问题）
- SE 前缀信息：5:8–12
- 历史导航：9:57、10:37–39
- backlog 图标：14:13–19、14:21–24
- 文字动画：2:47
- 其他：3:59、18:54，以及 host 查询 18:88/89/91/96–99

18:90 不一致（trenka 不弹参数），因此排除。

**决策**：新增 `NativeBuild::Trenka`，按完整文件哈希识别，并维护一张逐坐标的共用表 `NativeBuild::shares_registered_extcall`。`registered_softpal` 本身不打开，所以字体、输入、按钮的行为保持不变。`trenka_cn.exe` 不能列为候选文件名：任何一个候选文件对不上哈希，都会让整套安装被判为 Unknown。

**运行时**：5:8、18:88/89/96… 等调用不再报 unimplemented。backlog 里出现了角色头像和语音图标。SE 现在按 lane/前缀音量播放。

## 2. `.ANI` 动作程序（`d41226e`）

**原生证据**：

- 加载：`0x4473E0`，文件最后一个 dword 是入口偏移，label n 位于 `len-0xC-4n`
- 解释器：`0x4466A0`，opcode 0x00–0x16 加上 0xFC–0xFF
- 每帧驱动：`0x446FE0` / `0x447060`
- 清除：`0x447180`
- 各任务回调：`0x402FF0..0x404440`

缓动曲线：mode 1 为 `log10` ×55，mode 2 为 `log10` ×80，mode 4 为 `sin`；op 0x15/0x16 使用 512 项正弦表。`0x13` 是“持久化”标志。程序挂上 sprite 后立即执行，直到第一个等待指令。Koikake 的 `.ani` 用的也是同一种编码。

**实现**：新增 `ani.rs`，是一个完整的解释器；SpriteSystem 为每个 sprite 维护一个播放器；新增 `PalSprite::motion_lanes`，与 action lanes 叠加；3:33 `sp_anime_clear`。

**验证**：本作 351 个程序全部能解析和运行（临时探针，没有提交）。开场线条特效、存档界面 “NEW!” 的缩放、精灵表动画都在动。

**sp_set_pos_ex（3:14）**：trenka `0x429060` 写 wrapper 的基础位置（int +0x10..0x18、float +0x6C..0x74，与 `sp_create` 写的是同一组字段），等于绝对移动；审计过的 Game.exe 写旋转层，所以按 `NativeBuild` 区分。第一版把它实现成叠加在基础位置上的独立图层，导致 TIPS 小窗口的坐标被算了两遍（(8,334) 变成 (16,668)），`41b633d` 已改正。“NEW!” 仍出现在新存档位的左上角。

## 3. action 段类型 16 / 20（`a3003f3`）

- 17:31（`0x40A230`，类型 16）：source rect 补间
- 17:35（`0x409170`，类型 20）：用 mask 图逐像素显现目标 sprite 的 alpha（`0x401DF0`），结束时把 from 整块复制到 to（`0x402010`）

剧情里的斩击特效原来一直是黑屏，现在能正常显示。四张按类型索引的函数表分别位于 `0x625EE8`、`0x625F40`、`0x625FA0`、`0x626000`。

## 4. 存档标签（`a3ddd58`）

- 缩略图回退：只有本次会话里真正存过的槽位，才允许用内存里的缩略图代替；原来空槽位会显示当前画面
- 字体：原生 `0x42F420` 会应用整组存档字体设置（字号、字体类型、效果、两个颜色），然后恢复；sena 原来强制最小字号 18，导致日期和时间重叠
- 台词：按 `0x431C30` 的规则换行和截断

## 5. TIPS 词典与其他 cat 18 扩展（`94d9502`、`e61317a`、`6734cf4`）

- 18:82–87：读取 4 列 CSV（名称、读音、小图、大图）、五十音行号、两个标志字节、`tips_acc.dat`
- 18:50 / 18:59：存档目录与字符串拼接；文件访问被限制在 `save/` 目录之内
- 18:72 / 73 / 79：全局整数表
- 18:108：场景跳过锁存位

**相关修复**：

- `getprivateprofileint` 现在按 Windows 的规则解析开头的整数。原来 `TIPS_FLAG = 1;` 被读成默认值 0，导致 TIPS 被关闭。
- 四个 INI 函数的文件名改为按 File.dat 解析（原生 `0x44B500`）。

**运行时**：首次启动时读到 `TIPS_FLAG=1`，`tips_csv_read "tips.csv" entries=272`，并写出了 `save/tips_acc.dat`。TIPS 画面能显示五十音分类标签。

## 6. 版本专属 extcall 的登记方式（`41b633d`）

trenka 自己新增、或者参数约定与 registered 版本不同的 wrapper，统一登记在 `TRENKA_OWN_EXTCALLS` 表里，由 `NativeBuild::defines_extcall(cat, idx)` 判定。这样不需要为每个功能单独加一个谓词。表中坐标：3:32、3:58、8:27、8:31–32、14:25、18:50/57/59–68/72/73/79/82–87/106–108。

## 7. 收藏语音与 backlog 分隔线（`849c2fd`、`4dcdd9a`、`2fd7102`）

**原生证据**：
- 18:60–68（`0x414CA0..0x4154B0`）：最多 0x400 条记录（id、flag、名字、语音、去掉标签的正文），文件格式是每行 `%06d,%1d,"name","voice","text"`；18:79 设置上限（INI `FAV_MAX`）。
- backlog 里点角色头像按钮时，会依次调用 14:20 取这条记录，用 18:107（动态字符串的字节长度）判断有没有语音，然后调用 18:61 添加、18:65 保存。
- 18:57 `strcut`（`0x41B7C0`）：按前导字节数字符（CR/LF 算一个），超出上限时在 `2*limit` 字节处截断（如果该位置不是前导字节，就多留一个字节），返回字符数。18:106 只是把一个字节转给 `PalSetPow`（强制显卡纹理为 2 的幂），对移植版没有可见影响。
- 14:25（`0x42D1A0`）：参数是开关、File.dat 名字、x、y。脚本传入的是 `[history] HISTORY_LINE_*`，也就是 backlog 的**分隔线**，并不是收藏图标。builder `0x42B7A0` 在每条可见记录上画这个 sprite，位置为 `anchor - (行高 - 图高)/2 + y`，超出视图上沿的行不画。
- 3:32 `sp_create`（`0x4267D0`）在 trenka 里有 6 个参数：slot、File.dat 名字、x、y、宽、高（`#AARRGGBB` 会生成宽×高的纯色画布）。
- 3:22 `sp_text`（`0x427520`）：slot 里已有 sprite 时，调用 `PalSpriteCreateTextEx` 把文字画进现有表面（不清空、不移动）；Totsulover `sub_449B90` 也是这样。sena 原来会把整个 sprite 替换成文字，这个修正对所有版本生效。

**运行时**：点击 backlog 头像后写出了 `save/favoice.dat`（1 条记录）；EXTRA → VOICE MODE 显示 “VOICE: 001/500”、头像，以及经过 strcut 截断、末尾带 “…” 的台词；backlog 每条记录之间都有分隔线，滚动后位置正确。

## 8. 游戏内 TIPS（`41b633d`）

**问题**：本作台词里用 `<dN>…</d>` 标出 TIPS 词条（TEXT.DAT 中共 59 处）。sena 把台词交给 ADV 渲染器之前，就已经把所有标签剥掉了，所以 tips layout 从来没有生成过记录：词条不会高亮，也不能点击。

**原生证据**：
- 文本 task 每个 tick 都会回调脚本（point 2084）。回调里用 3:32 建一个 197×96 的画布；用 3:58 `drawtext`（`0x42A3F0`，用文本窗口的渲染器 `0x43CC30` 排版折行文字）画出普通、悬停、按下三种状态；再用 8:27 `btn_blt`（`0x40FEA0`）把画布变成按钮，盖在词条上；8:31/8:32 在按钮记录 +0x4C 存取词条 id。
- 点击这个按钮后，会在 (8,334) 弹出 TIPS 小窗口（`tipsS*` 图加 `ANI_TIPS_FADEIN`）。
- point 2233 只在“场景跳过”生效时（18:108 返回非 0）才静默登记词条，平时的登记走上面的回调。

**实现**：ADV 渲染器拿到的是保留标签的原文；实现了 3:58、8:27、8:31/32。另外，文本块的高度改为按每行实际步进计算，三行台词的最后一行不再被裁掉。

**运行时**：共通线第一个 TIPS 词条（auto-advance 下约第 28440 帧）以绿色高亮显示；点击后小窗口出现在 (8,334)，标题和说明文字都正确。EXTRA → TIPS 的列表和详细说明也能正常显示。

## 9. extcall 参数个数审计（`c3509db`、`9eb2274`、`1b6eaa0`、`073f950`）

**方法**：
- 先从 30000 帧 `--trace-script` 日志里统计每次调用前后的栈深度差（覆盖 195 个坐标）。
- 再用一个临时探针（没有提交）把脚本用到的全部 419 个坐标逐个以 trenka 身份调用，记录弹出的个数。
- 两种结果都和原生 handler 比对：数 `not stack` 检查的次数，加上调用弹栈 helper `0x44B3E0` 的次数。

**修正**：
- 3:13 `sp_cls_transition`：弹 3 个（slot、过渡类型、时长），带淡出地清除。原来按 1 个弹，每次调用往栈上留 2 个值。
- 9:55 `get_font_color`：弹 1 个选择子（0 取文字色，否则取效果色）。Reference 版也是这样，所以对所有版本生效。
- 2:18 `text_n` / 2:19 `text_cat`：各弹 4 个。sena 原来把它们当成不弹栈的空操作，结果这两处剧情台词根本不显示。现在 `text_n` 正常显示但不进 backlog，`text_cat` 把正文接在当前台词后面。
- 2:20 `set_history`：弹 3 个，只往 backlog 写一条记录。脚本配合 text_n/text_cat 使用，用它补上完整的那一行。
- 3:38 `sp_bitblt`：弹 9 个，sprite 到 sprite 的拷贝（33 处调用）。
- 9:48 `set_cursor`：弹 3 个。
- 10:29：弹 2 个，通过 `save_tmp.dat` 交换两个存档位，也就是存档界面的“データ移動”。
- 18:17：不弹栈。
- 8:42 `btn_set_invalid_time` 与 registered 版本一致，加入共用表。
- 2:35、3:42/43、4:5、4:16/17、8:28/30、15:1/9、18:43–48、18:76、18:109、18:113–115：集中放在 `runtime/trenka_wrappers.rs`，按原生个数弹栈。截图导出、编辑对话框、tweet 等宿主功能返回中性结果；文件读写只允许在存档目录内。

**结果**：419 个坐标的弹栈个数全部和原生一致。只剩两处数字表面上不同，都已确认：18:9 `wsprint` 在循环里弹出脚本填充的参数；11:2 通过函数指针调用 3:5 `sp_cls`，弹 1 个。

**运行时**：在存档界面依次点“データ移動”、选源位、选目标位、确认，存档从第 6 位移到了第 4 位（`save005.dat` 变成 `save003.dat`）。

## 未解决

- **EXTRA 子菜单偏左**：已经逐层核对过原生：17:29 的 append（`0x40A650`）、packed 引用解析（`0x449110`：wrapper = 0x90 + group·128 + index）、类型 15 的求值（`0x4081E0`，sin(t·π/2)）和结束回调（`0x408350`，把完整偏移累加进 wrapper +0x12C）。sena 的处理与原生一致。标题动画结束时主菜单停在 +100，子菜单停在 −100，所以“偏左”很可能就是原生的样子。按钮图像的不透明区域是 x 0–303。没有原生截图对照，暂时记为“大概率忠实”。
- **选项**：脚本里没有 6:1/6:2/6:3（`select`/`select_set`/`select_commit`），只有 `select_init`/`select_clear`/`select_set_process`，所以本作没有原生的选项块。600000 帧共通线自动推进时也没有出现任何选项。之前推测“选项用 3:58 实现”是错的，3:58 其实是 TIPS 用的。`MAIN_SELECT` 只在 point 2344/2345 的 `select_init` 里出现，而这两个 point 没有直接调用者。
- tweet / 截图类（18:41–48）、18:55 文本保存等仍是 Skip。
- 3:58 结束时原生会调用 `PalSpriteSetRect`，把 sprite 的显示区域裁到文字范围。移植版没有做这一步（画布本身是透明的，目前看不出差异）。
- 存档界面 “NEW!” 被存档位底板（按钮层）部分遮挡：sena 的优先级公式和原生一致，暂不改动。
